# Etap 01 — audyt i bezpieczny fundament odczytu

## DONE

Audyt obu lokalizacji, Git, katalogu źródeł, schematów i wybranych komponentów. Potwierdzono istniejący aktywny MT5 DEMO przez GET, bez sterowania. Ustalono rozdzielenie źródeł/strategii i DATA pomiędzy lokalnymi bazami. Przygotowano plan integracji bez migracji runtime.

W istniejącym rdzeniu zaimplementowano:

- odczyt stanu i listy strategii bez inicjalizacji/migracji bazy;
- graf rzeczywistych referencji, dokładne wersje i jawne braki/niejednoznaczności;
- ochronę historii records oraz dodatkową ochronę events przed SQL REPLACE;
- nowe snapshoty Alpaca bez nadpisywania istniejących plików, także przy wyścigu publikacji;
- zachowanie brakujących pól danych zamiast ich fabrykowania.

## TESTS / EVIDENCE

Przed poprawkami nowe testy wykazały możliwość zmiany/usunięcia rekordów i zastąpienia zdarzenia przez REPLACE; nowe komendy nie istniały. Testy snapshotów wykazały brak ochrony istniejących plików i fabrykowanie pól opcjonalnych.

Po poprawkach: **70/70** testów rdzenia na Python 3.12.10 (12,613 s). Wcześniejszy przebieg z read mode/historią: 67/67 na Python 3.14. Wybrany zastany frontend: **31/31** testów JS oraz `tsc --noEmit --incremental false`, exit 0. Nie wykonano publikacji/build produkcyjnego frontendu.

Migracja v4 → v5 i ponowna inicjalizacja zostały sprawdzone na bazie tymczasowej z zachowaniem wcześniejszych rekordów i zdarzeń. Próby UPDATE/DELETE/REPLACE kończą się odmową, nowa wersja jest dopisywalna. Odczyty CLI sprawdzono na realnych lokalnych bazach: pozostały v1/v3/v4. Graf nie zalicza wspólnych DATA/SRC jako związku między różnymi strategiami.

## BLOCKERS

GitHub: brak dostępu Git. Wspólny model D1/local/MT5 nie jest wdrożony. Źródła, szkic BTC/ETH i DATA nie tworzą jeszcze jednego eksperymentu. Brak części jawnych wersji referencji. Zakres autorytatywnego runtime i fizyczne ścieżki baz AppData wymagają rozstrzygnięcia przed ich migracją. Szkic strategii wymaga nadal decyzji o regułach/kosztach; to nie blokuje prac programistycznych.

Pełny test odbiorowy z briefu **nie jest zaliczony**. Maszyna stanów, kompletne przeglądy, uwierzytelnione zatwierdzenia, integracja panelu i nowa ścieżka DEMO nie są gotowe. Nie należy raportować tego etapu jako działającego bota przynoszącego dochód ani pełnego audytu bezpieczeństwa.
